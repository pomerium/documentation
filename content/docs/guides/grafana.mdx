# Secure Grafana with Pomerium

## What this guide does

Put Grafana behind Pomerium to gate it with SSO and route policy. Grafana keeps its standard OpenID Connect (OIDC) login, and Pomerium is the OIDC provider. Users sign in once through Pomerium, and Grafana completes its login without a second prompt.

```mermaid
sequenceDiagram
  participant B as Browser
  participant P as Pomerium
  participant G as Grafana
  B->>P: Open https://grafana.yourdomain.com
  P->>B: Sign in at the IdP, once
  P->>G: Proxy the request
  G->>B: Redirect to Pomerium's authorization endpoint
  B->>P: GET /oidc/auth
  P->>B: Redirect back with a code, no prompt
  B->>G: Callback with the code
  G->>P: POST /oidc/token
  P->>G: ID token and access token
```

## When to use this guide

Use it when you want one front door for Grafana with your existing identity, and Grafana should keep its own OIDC login. It uses Grafana's generic OAuth login, which works with Pomerium's [OIDC bridge](/docs/capabilities/oidc-bridge). If you only need to reach Grafana over a private network without browser SSO, a plain [TCP route](/docs/capabilities/non-http) is a better fit.

## Prerequisites

- [Docker](https://docs.docker.com/install/) and [Docker Compose](https://docs.docker.com/compose/install/)
- Pomerium Core with a self-hosted authenticate service on a domain you control (this guide uses `authenticate.yourdomain.com`). The OIDC bridge isn't available on the hosted authenticate service.
- An OpenID Connect identity provider. This guide uses [Keycloak](/docs/integrations/user-identity/oidc) as the example.
- A domain you control for the Grafana route (this guide uses `grafana.yourdomain.com`)

:::tip Need an identity provider?

Follow [Keycloak + Pomerium](/docs/integrations/user-identity/oidc) to set one up, then fill in the `idp_*` settings in `config.yaml` with your client ID and secret.

:::

## Configure Pomerium

Create a `config.yaml`. It routes `grafana.yourdomain.com` to the Grafana container, enables the OIDC bridge on that route, and sets the `shared_secret` that Pomerium uses to sign and encrypt the tokens it issues.

</CodeBlock>

Replace `grafana.yourdomain.com` with your domain, `you@example.com` with your email, and generate your own `shared_secret` with the command in the comment. The route's `from` URL is the OIDC client ID that Grafana uses, so it must match `GF_AUTH_GENERIC_OAUTH_CLIENT_ID` in the next section. Keep `shared_secret` the same across restarts. If it changes, Pomerium can't read tokens it issued earlier, and users have to sign in again.

## Configure Grafana

Grafana's generic OAuth login talks to Pomerium's OIDC endpoints. The key settings are in the `grafana` service of the Compose file below:

- `GF_SERVER_ROOT_URL` — Grafana's public URL. Grafana builds its callback from it: `https://grafana.yourdomain.com/login/generic_oauth`.
- `GF_AUTH_GENERIC_OAUTH_CLIENT_ID` — the route's `from` URL.
- `GF_AUTH_GENERIC_OAUTH_USE_PKCE=true` — Grafana uses PKCE, so no client secret is needed.
- `GF_AUTH_GENERIC_OAUTH_AUTH_URL`, `_TOKEN_URL`, and `_API_URL` — the `/oidc/auth`, `/oidc/token`, and `/oidc/userinfo` endpoints on your authenticate service.
- `GF_AUTH_GENERIC_OAUTH_EMAIL_ATTRIBUTE_PATH` and `_LOGIN_ATTRIBUTE_PATH=email` — which claim becomes the Grafana account.
- `GF_AUTH_GENERIC_OAUTH_ALLOW_SIGN_UP=true` — create the Grafana user on first sign-in.
- `GF_AUTH_GENERIC_OAUTH_ROLE_ATTRIBUTE_PATH` — optional role mapping. Pomerium sends every claim as a string, so a `groups` claim arrives as a comma-separated string such as `"grafana-admins,developers"`. That's why the expression uses `contains()`. It only works if your identity provider sends a `groups` claim.

## Verify the setup

1. **The route requires authentication.** In a fresh browser, open `https://grafana.yourdomain.com`. You should be redirected to Pomerium to sign in.
2. **Grafana offers Pomerium login.** After you sign in, the Grafana login page shows a **Sign in with Pomerium** button. Select it.
3. **The OIDC login completes without a prompt.** Grafana signs you in. Open `/profile` and confirm your email shows.
4. **A disallowed user is blocked.** Sign in as a user your policy excludes and open `https://grafana.yourdomain.com`. Pomerium denies access before Grafana loads.

## Common failure modes

| Symptom | Cause and fix |
| :-- | :-- |
| `404 Not Found` from Grafana's OAuth URLs or the `/oidc/` paths | Grafana is pointing at the wrong host. Check that `authenticate_service_url` is set and that the `GF_AUTH_GENERIC_OAUTH_*_URL` values use the same host. |
| HTTP 400 at `/oidc/auth`: `redirect_uri ... does not match client_id ...` | `GF_AUTH_GENERIC_OAUTH_CLIENT_ID` doesn't match the route's `from` URL, or `GF_SERVER_ROOT_URL` isn't the Grafana URL. |
| Token request fails with `invalid_client` | The Grafana OAuth client authenticates with HTTP Basic and leaves `client_id` out of the request body. Set `GF_AUTH_GENERIC_OAUTH_AUTH_STYLE` so the credentials are sent in the body, and check the option's value in your Grafana version's docs. |
| Users still see two login prompts | Grafana's password form appears first. Set `GF_AUTH_DISABLE_LOGIN_FORM=true` so Pomerium is the only login option. |
| Everyone is a Viewer | The `groups` claim is missing from the identity provider's tokens, or the expression doesn't match the group names. Confirm your identity provider sends `groups` and that the names match exactly. |
| `invalid_token` on Grafana's user info request | The access token was issued before Pomerium restarted without a fixed `shared_secret`. Set `shared_secret` and sign in again. |

## Security considerations

- **Keep the route protected.** The bridge handles login only. Route policy decides who can reach Grafana, and Pomerium checks it on every request. A public route would let anyone who can sign in to Pomerium get a Grafana account.
- **Only Pomerium should reach Grafana.** Keep `grafana:3000` off published ports and on the internal Docker network, so Pomerium is the only way in.
- **Pomerium issues the tokens.** Grafana gets its ID and access tokens from Pomerium, not directly from your identity provider.
- **No refresh tokens.** When the Pomerium session expires, the next request sends the user back to Pomerium to sign in.
- **PKCE means no client secret.** If you later use an app that can't do PKCE, the bridge supports a `client_secret` on that route. Keep it secret.
- **Account creation follows the policy.** `GF_AUTH_GENERIC_OAUTH_ALLOW_SIGN_UP=true` creates a Grafana account for every user your policy allows. Manage Grafana org roles separately, or use the role mapping above.
