# Identity Providers (per route)

## Summary

**Identity Providers (per route)** narrows which of the globally-declared [`identity_providers`](/docs/reference/identity-providers) are accepted on this route. It is an allowlist of provider names.

This setting is only meaningful on a route whose effective [bearer token format](/docs/reference/bearer-token-format) is `jwt`. When left unset, the route accepts a token from **any** configured provider. When set, a token whose provider is not on the list is rejected before its signature is checked.

Names are matched against the global `identity_providers` map at request time, not at startup. A name that is not declared there — because it was never added, or because it was removed later — is not a configuration error and does not prevent Pomerium from starting; it simply never matches, so tokens from that provider are rejected. Note that removing a name from this list is not the same as leaving the list empty: an empty list accepts **any** configured provider, so narrowing a list down to nothing widens the route rather than closing it. This setting is ignored on a route whose effective bearer token format is not `jwt`.

See [Machine-to-Machine Access with Bearer Tokens](/docs/capabilities/bearer-token-access) for an overview and examples.

## How to configure

<Tabs>
<TabItem value="Core" label="Core">

| **YAML**/**JSON** setting | **Type**          | **Usage**    |
| :------------------------ | :---------------- | :----------- |
| `identity_providers`      | array of `string` | **optional** |

### Examples

```yaml
routes:
  - from: https://api.localhost.pomerium.io
    to: http://api-backend
    bearer_token_format: jwt
    identity_providers:
      - kubernetes
    policy:
      - allow:
          and:
            - claim/sub: system:serviceaccount:default:pom-tester
```

</TabItem>

